# SCHOOL ATTENDANCE — приглашения (backend patch)

## Зафиксированные правила
- Срок действия каждого приглашения: 24 часа.
- Только `SUPER_ADMIN` может создавать приглашения и отзывать их.
- Поддерживаются только роли `ADMINISTRATOR` и `EMPLOYEE`.
- Обычная регистрация не назначает роль; роль выдаётся только серверной callable-функцией `redeemInvite`.
- Код одноразовый, хранится в Firestore только SHA-256-хешем и показывается создателю один раз.
- Приглашение привязано к одной школе.

## Состав архива
- `functions/src/invitations.ts` — серверные функции create/redeem/revoke/list.
- `functions/src/index.ts` — экспорт этих функций (на основе исходного index.ts из проекта).

## Установка
1. Сделайте резервную копию папки `functions/src`.
2. Распакуйте архив в корень существующего проекта `D:\Projects\SCHOOL_ATTENDANCE\school-attendance`, сохранив структуру папок и разрешив замену `functions/src/index.ts`.
3. Из корня проекта выполните:
   ```powershell
   npm.cmd run build
   npm.cmd test
   ```
4. Не запускайте deploy автоматически. Сначала проверьте сборку и тариф Firebase.

## Вызов из клиента
После успешной регистрации Firebase Auth вызовите `redeemInvite` через `httpsCallable(functions, 'redeemInvite')` с `{ code }`. После успешного ответа обновите ID token (`getIdToken(true)`) и заново загрузите профиль.

Создание приглашения: `createInvite({ role: 'ADMINISTRATOR' | 'EMPLOYEE', schoolId })`.
Список: `listInvites()`.
Отзыв: `revokeInvite({ codeHash })`, где `codeHash` — ID приглашения, возвращённый сервером только в административном списке. Сам код повторно не возвращается.

## Важные ограничения / обязательная интеграция
- Это backend patch, не готовая UI-панель: экран управления приглашениями и экран ввода кода нужно подключить отдельно к callable functions.
- В текущем проекте необходимо проверить поток регистрации: он не должен самостоятельно писать `role`, `schoolId` или `ACTIVE` в профиль. Пользователь без приглашения должен оставаться `PENDING`.
- Текущие Firestore Rules должны запрещать клиентскую запись в `invites`, `users.role` и `users.schoolId`. Admin SDK обходит Firestore Rules; клиентские записи должны быть закрыты.
- Существующие `SUPER_ADMIN` claims должны быть назначены только отдельной защищённой одноразовой bootstrap-процедурой. Приглашения не могут выдавать `SUPER_ADMIN`.
- После `setCustomUserClaims` клиент обязан обновить ID token.
- Повторный вызов `redeemInvite` тем же UID безопасно восстанавливает назначение claims, если предыдущая попытка оборвалась после фиксации использования кода.
- Для развёртывания Firebase Cloud Functions проект может потребовать план Blaze и привязку биллинга. Этот архив ничего не разворачивает и не меняет тариф. Не переходите на Blaze без отдельного согласия.

## Проверки
После установки выполните build/test. Перед production-развёртыванием дополнительно протестируйте в Firebase Emulator Suite: неверный код, истёкший код, повторное использование, отзыв кода, попытку вызова не-Super-Admin и два параллельных погашения одного кода.
